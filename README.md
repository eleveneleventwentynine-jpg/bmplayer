# bmplayer

A next-gen media player for audio, video, and streaming, built in Flutter
with a glassmorphic "Ambient Bloom" design system: frosted glass surfaces
floating over a background that tints itself from whatever's currently
playing.

## What's new

- **Persistence (sqflite).** `lib/services/database_service.dart` stores
  playlists and favorites in a real SQLite database
  (`lib/state/playlists_controller.dart`, `favorites_controller.dart`).
  Long-press a playlist card on Home to rename/delete it; tap "New
  playlist" to create one; tap the heart on the now-playing sheet to
  favorite a track — all of it survives app restarts.
- **Queue / reorder.** The now-playing sheet's "⋯" button opens a
  draggable "Up next" sheet (`lib/features/now_playing/queue_screen.dart`)
  — reorder by dragging, tap any row to jump to it, tap ✕ to remove.
  Backed by `PlayerService.reorderQueue/removeFromQueue/jumpTo`, which
  track the currently-playing item by identity so a reorder never causes
  a surprise playback jump.
- **iOS pass.** `LibraryService` now requests audio (Apple Music /
  MPMediaLibrary) and video (Photos) permissions independently, since iOS
  treats them separately, and degrades gracefully if only one is granted.
  `PlayerService` configures `audio_session` on startup so background
  playback, lock-screen controls, and interruption handling (phone calls,
  other apps, headphones unplugged) behave correctly — this also improves
  Android audio-focus behavior, not just iOS.

## What's here

This is the `lib/` source tree — the app's architecture, theme, state
management, and every screen — wired together and ready to run against
demo data. Platform folders (`android/`, `ios/`) aren't included since
they need to be generated by the Flutter CLI on your machine (see setup
below).

```
lib/
  core/
    theme/            Colors, type system, ThemeData
    widgets/           GlassContainer, AmbientBackground, AnimatedWaveform
  models/               BmMediaItem, BmPlaylist, StreamingSource interface
  services/
    player_service.dart Unified play/pause/seek/skip over just_audio + video_player
    demo_data.dart       Placeholder catalogue — swap for real data
  state/
    providers.dart       All Riverpod providers
  features/
    home/                 Continue-listening carousel + library + playlists
    library/               Full local library, split by audio/video
    discover/               Search + streaming results
    now_playing/            Full-screen player sheet (art or video + controls)
  widgets/
    mini_player.dart        Floating glass mini-player
    glass_nav_shell.dart     App shell: nav dock + mini-player + expandable sheet
  main.dart
```

## Design system

- **Palette:** void black (`#0A0B14` → `#050609`), glass surfaces at ~6–10%
  white opacity, Pulse Violet `#8B7FFF`, Drift Aqua `#45E8D1`, Flare Coral
  `#FF7092` for active states.
- **Type:** Outfit (display/headlines), Inter (body/UI), JetBrains Mono
  (timestamps, bitrate, and other technical metadata).
- **Signature detail — Ambient Bloom:** `AmbientBackground` extracts the
  dominant color from the current track's artwork (via `palette_generator`)
  and tints the whole app's backdrop to match, animating smoothly between
  tracks. `AnimatedWaveform` gives any "now playing" surface a live pulse.

## Setup

1. Install the Flutter SDK (stable channel) if you haven't already:
   https://docs.flutter.dev/get-started/install

2. Generate platform folders in this directory:
   ```
   flutter create --project-name bmplayer --org com.yourname .
   ```
   This adds `android/`, `ios/`, etc. without touching `lib/` or
   `pubspec.yaml` (answer "yes" if it asks to overwrite — it only touches
   platform scaffolding, not your Dart code).

3. Fetch packages:
   ```
   flutter pub get
   ```

4. Add permissions:

   **Android** (`android/app/src/main/AndroidManifest.xml`, inside `<manifest>`):
   ```xml
   <uses-permission android:name="android.permission.INTERNET" />
   <uses-permission android:name="android.permission.READ_MEDIA_AUDIO" />
   <uses-permission android:name="android.permission.READ_MEDIA_VIDEO" />
   <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
   <uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />
   ```
   Also set `minSdkVersion 21` or higher in `android/app/build.gradle`.

   **iOS** (`ios/Runner/Info.plist`):
   ```xml
   <key>NSAppTransportSecurity</key>
   <dict><key>NSAllowsArbitraryLoads</key><true/></dict>
   <key>UIBackgroundModes</key>
   <array><string>audio</string></array>
   <key>NSAppleMusicUsageDescription</key>
   <string>bmplayer needs access to your music library to play your songs.</string>
   <key>NSPhotoLibraryUsageDescription</key>
   <string>bmplayer needs access to your video library to play your videos.</string>
   ```
   `NSAppleMusicUsageDescription` covers `on_audio_query`'s access to the
   Apple Music / MPMediaLibrary catalogue; `NSPhotoLibraryUsageDescription`
   covers `photo_manager`'s access to videos. bmplayer requests these as
   two independent permissions (see `LibraryService.requestPermissions`)
   and will still show whichever half was granted if the person only
   allows one.

5. Run it:
   ```
   flutter run
   ```

## Wiring up real media

- **Local library — already wired.** `lib/services/library_service.dart`
  scans audio via `on_audio_query` and video via `photo_manager`, gated by
  `lib/state/library_controller.dart` (handles permission requests, load
  state, and play history for "Continue listening"). It runs automatically
  on app start (`GlassNavShell.initState`) and falls back to the demo
  catalogue if permission is denied or the device has nothing to show.
- **Streaming — already wired.** `lib/services/youtube_streaming_source.dart`
  implements `StreamingSource` using `youtube_explode_dart` (pure Dart, no
  bundled yt-dlp binary needed). Search results resolve instantly; the
  actual signed stream URL is fetched lazily right before playback in
  `resolvePlaybackUri()`, since those URLs expire. Swap in a different
  `StreamingSource` implementation any time — nothing else in the app
  needs to change.
- **Persistence:** add `shared_preferences` or `sqflite` for playlists,
  favorites, and playback history if you want them to survive restarts —
  currently play history lives only in memory for the session.

## Building an APK via GitHub Actions

`.github/workflows/build_apk.yml` builds a debug APK on every push/PR, and
a signed, split-per-ABI release APK + GitHub Release when you push a tag
like `v1.0.0`.

To get **signed** release builds, add these as repo secrets under
**Settings → Secrets and variables → Actions**:

| Secret | Value |
|---|---|
| `KEYSTORE_BASE64` | Your `.jks` keystore file, base64-encoded (`base64 -i your-key.jks \| pbcopy` on macOS, or `base64 -w0 your-key.jks` on Linux) |
| `KEYSTORE_PASSWORD` | Keystore password |
| `KEY_ALIAS` | Key alias |
| `KEY_PASSWORD` | Key password |

Without these secrets, the workflow still builds successfully — it just
falls back to Flutter's default debug signing, with a warning in the
Actions log, which is fine for testing but not for a Play Store upload.

## Notes

- `PlayerService` (in `services/player_service.dart`) is the single choke
  point for playback — it picks `just_audio` or `video_player` per item
  based on `MediaKind`, so screens never talk to either engine directly.
  This is also where you'd add gapless playback, crossfade, or a queue
  reorder feature later.
- The now-playing sheet is not a route — it's an `AnimatedPositioned`
  overlay in `GlassNavShell` driven by `playerExpandedProvider`, so it can
  slide up over any tab without losing that tab's scroll position.
